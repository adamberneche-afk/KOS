**Standing rules**

- **The agent never touches the live Google account** (SMP-004). The
  operator runs every `clasp` command, Apps Script function and Studio edit,
  and pastes results back.
- PRs are opened only when the operator asks, and merged only on the
  operator's explicit "merge".
- Work happens on `claude/kos-personal-handoff-review-yc4gp1`. After each
  merge it is reset to `origin/main` and force-pushed.
- No student or district data in the repo, in a notebook source, or in a
  commit message.

**Repo conventions that bite**

- After changing a project's files, run
  `node tools/deploy-drift/stamp.js <project>` (`kos-personal`,
  `leader-hub:app`, `cas-ccps:<project>`) and commit the marker on its own.
  A cherry-pick or rebase changes the SHA, so it needs a fresh stamp.
- A new file under `tests/` needs the root `README.md` touched (CI
  docs-check). A new `.gs`/`.js` needs `tools/gas-lint/project-map.json`.
- LeaderHub is edited in `leader-hub/src/*.html`, then
  `node tools/leaderhub-build/build.js`; the built
  `student-leader-hub.html` is committed. Several tests extract fixed line
  ranges from the fragments (`tests/harness/extract-lines.js`); an edit
  above a range shifts it, and the test says which range to re-find.
- Checks to run before a push: `npm test`, `node tools/gas-lint/check.js`,
  `node tools/doc-currency/check.js`, `node tools/coverage-gaps/check.js`
  (slow, about two minutes), `node tools/clasp-sync/sync.js`, and for
  LeaderHub `node tools/html-lint/check.js leader-hub/student-leader-hub.html`.
