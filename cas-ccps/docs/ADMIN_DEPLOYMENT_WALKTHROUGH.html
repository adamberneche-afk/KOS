Admin Deployment walkthrough: retired

Do not follow any older copy of this page. It was retired on 2026-10-22 because it had fallen years behind the code (it described 7 scripts; there are now about 70 script files across 9 projects) and one of its steps was unsafe.

It told you to deploy the Student Dashboard as "User accessing the web app" with access "Anyone with a Google account". That setup only works if every student can open the whole Central Ledger, which holds every student's records. The real setting is below.

The web-app settings, from the manifests

The manifests in cas-ccps/clasp/manifests/ are the source of truth. run.js pushes them as written, so you never choose these settings by hand.

ProjectExecute asWho has access
student-dashboardUSER_DEPLOYING (Me, the deploying admin)DOMAIN (anyone in your Workspace domain)
teacher-dashboardUSER_DEPLOYINGDOMAIN

The other cas-ccps projects have no web app. The Student Dashboard runs as the admin and shows only the rows that match the signed-in student, so students need no access to the Ledger. If students were given Ledger access under the old instructions, run previewStudentDataAccessRepair() in the Central Ledger project: its log says how many student accounts the Ledger is shared with (a count; the log names no student). Remove those by hand (Share, in the Ledger). Each Teacher Dashboard opens only for the account in its TEACHER_EMAIL Script Property. Both dashboards need CENTRAL_LEDGER_SS_ID; ADMIN_SS_ID, when unset, defaults to the same spreadsheet (00_SharedConfig.js).

How deployment works now

  • tools/clasp-sync/run.js pushes every project. A registry folder outside the repo holds each project's real .clasp.json and, for a web app, a deployments.txt listing the deployment IDs to keep live.
  • For a web app, run.js pushes, cuts one version and points every deployment in deployments.txt at it. Do not make a web-app version or a new deployment by hand: the deployment IDs, and so every /exec link, stay the same.
  • To roll back one project: node run.js --rollback-to <version> --only <project>.
  • studio-steps is not deployed.
