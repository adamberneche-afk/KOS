Phase 1 — Prepare
1

Confirm Prerequisites

Before you write a single line 5 min
1

Confirm your Google Workspace plan includes Workspace Studio

Workspace Studio (and the native Gemini connector) is available on Google Workspace for Education Plus, Business Starter and above, and Enterprise plans. Log into admin.google.com → Apps → Google Workspace → Workspace Studio, and verify it is enabled for your organization.

🚫
This is a hard requirement. The system has no fallback inference path. If Workspace Studio is not available on your plan, the evaluation pipeline cannot function.
2

Designate the admin Google account

Pick one Google account that will own all system assets — spreadsheets, folders, forms, and scripts. This account runs every automated process. It does not need to be a special admin account — any Google account with Drive access works. Use it for all remaining steps.

3

Verify you have Drive storage available

The system creates roughly 8–12 Google Drive assets during setup plus one folder per teacher and one document per student over time. A standard 15GB Drive account is sufficient for a school of any size since Google Docs, Sheets, and Forms don't count against Drive storage.

4

Have teacher email addresses ready

You'll need each teacher's email address to share their Teacher Manual copy. Students need no email — they use any Google account. Have at least one teacher email ready now for the test pilot in Step 12.

Create the Admin Manual Document

The operational hub for the entire system 15 min
1

Create a new blank Google Doc

In your admin Google account, go to docs.google.com and create a blank document. Name it something like Assignment System — Admin Manual. This document becomes the operational hub — every teacher gets a copy of it.

2

Open the Apps Script editor

In the document menu bar, click Extensions → Apps Script. A new tab opens showing the script editor. You'll see one default file called Code.gs.

3

Create and paste four script files

For each file below, click the + button next to "Files" in the left panel, name it exactly as shown, then paste the corresponding script content.

00_SharedConfig
paste contents of 00_SharedConfig.js
16_UnifiedManualSetup
paste contents of 16_UnifiedManualSetup.js
19_ClonedSheetConfig
paste contents of 19_ClonedSheetConfig.js — required for writeConfigTab_()
20_SetupCheckpoint
paste contents of 20_SetupCheckpoint.js

Delete the default Code.gs file — right-click it → Delete.

⚠️
File names matter. Apps Script uses the file names as display labels and for debugging. Match them exactly, without the .js extension (Apps Script adds that automatically).
4

Save and close the editor

Press Ctrl+S (or Cmd+S on Mac) to save. Close the Apps Script tab. Return to your Google Doc.

4

Run the Setup Wizard

The wizard creates ~12 assets automatically Automatic — ~60 sec
1

Reload the document

Close and reopen your Admin Manual Google Doc, or simply refresh the browser tab. After reloading, a custom menu will appear in the menu bar: ⚙️ Assignment System.

💡
If the menu doesn't appear after refreshing, open Extensions → Apps Script and run the onOpen function manually once to trigger authorization.
2

Click ⚙️ Assignment System → 🚀 Run Admin + Teacher Setup

A Google authorization dialog will appear. This is expected — click Review Permissions, choose your admin Google account, then click Allow. This authorizes the script to create Drive assets on your behalf.

3

Follow the wizard prompts

Prompt 1: Admin email address ← receives system alerts Prompt 2: Organization name ← used in folder labels

Then three questions for your personal teacher setup:

Prompt 3: Your full name Prompt 4: Your email address Prompt 5: Your subject area ← e.g. Science, English

Wait ~60 seconds for asset creation

5

Read the Setup Details pages

When the wizard finishes, two pages are appended to your Admin Manual: an Admin Setup Details page and a Teacher Setup Details page. Scroll to the end of the document now and read them. They contain direct links to every asset the wizard created.

✅
Save these links. The admin page has direct links to the Central Ledger, the two master template sheets, and the Assignments folder. You will need them in the next steps.

The admin page also includes a Known Limitations section. Read it now — it describes the forensic check strength, the pipeline blocking behavior, and batch size recommendations.

Bind Scripts to the Central Ledger

7 scripts — one project — the operational hub 20 min
1

Open the Central Ledger Spreadsheet

Find the link in your Admin Setup Details page (end of your Admin Manual document). Click to open it — this is the spreadsheet the wizard created with five tabs.

2

Open Apps Script and create 7 files

Click Extensions → Apps Script. Delete the default Code.gs. Create one file for each script below — click + next to "Files", name it exactly as shown, paste the full contents, save.

00_SharedConfig
02_Form1_IntakeAndWorkspaceGenerator
03_QueueBridge
04_Form2_TurnInGate
06_StagingPipeline_Turnstile
10_AdminRecoveryPanel
18_FormSubmitDispatcher
3

Enable the Drive Advanced Service

In the left panel, click Services (+). Find Drive API and click Add. This enables the version history forensic check in Script 04.

4

Set one Script Property

Click Project Settings (gear icon) → Script Properties → Add script property:

ID_ADMIN_SPREADSHEET = [Central Ledger Spreadsheet ID]

The spreadsheet ID is the long string in its URL between /d/ and /edit.

5

Set 4 triggers

Click the clock icon ⏰ → + Add Trigger. Add these four, authorizing each when Google prompts:

Trigger 1dispatchFormSubmit — From spreadsheet — On form submit
Trigger 2bridgeQueue — Time-driven — Every 1 minute
Trigger 3backPropagateCompletions — Time-driven — Every 2 minutes
Trigger 4runStagingTurnstile — Time-driven — Every 1 minute
⚠️
Trigger 1 must call dispatchFormSubmit — not onFormSubmit. The name onFormSubmit is reserved by Apps Script and causes conflicts.

Set 2 Script Properties on this document

CENTRAL_LEDGER_SS_ID = [Central Ledger Spreadsheet ID] ADMIN_SS_ID = [Central Ledger Spreadsheet ID] ← same value as above

Student copies don't inherit Script Properties — Script 02 stamps the IDs as invisible text into each student doc at creation time. These properties only need to be set on the master.

4

Copy the document ID from its URL (string between /d/ and /edit). Open your Admin Manual → Extensions → Apps Script → Project Settings → Script Properties. Add:

MASTER_STUDENT_TEMPLATE_ID = [the doc ID you just copied]

Script 02 reads this ID every time a student is registered. Without it, student registration fails with a clear error message to the teacher.

Set Current Term & Activate Your Workspace

Two quick final items 3 min
1

Set the current academic term

Open the Central Ledger Spreadsheet. In the menu bar, click ⚙️ Admin Controls → 📅 Set Current Term. Enter the current term identifier — for example 2025-26 S1. This tags every new student registration with the term so dashboards can filter by year and semester.

💡
Update this at the start of each term. Past registrations are not affected — only new ones get the new term tag.
2

Activate your personal teacher workspace

Scroll to the Teacher Setup Details page in your Admin Manual. You'll see two activation links under ⚡ Two Quick Activation Steps. Open each link once and click Allow when Google prompts you. These connect your rubric upload form and your assignment review system.

✅
After clicking Allow on both links, your personal workspace is fully active. Proceed to the end-to-end test.
12

Run an End-to-End Test

Verify every component before going live 30 min
1

Upload a test rubric

Open your Rubric Upload Form (link in your teacher setup summary page). Submit a short but real rubric. Include a Google Doc URL as the prompt template — create a test doc with a few sentences first. You should receive a "Rubric Received" email within 30 seconds.

2

Confirm the review email arrives and confirm the assignment

Within a few minutes, you should receive a review email with a pre-filled confirmation link. Click it, verify the extracted fields look correct, and submit. You should then receive an activation email saying the assignment is LIVE.

If the review email doesn't arrive within 5 minutes, check the Central Ledger → RubricQueue tab. The row should show COMPLETE. If it shows PENDING_EXTRACTION, Studio Flow 1 did not trigger — verify the trigger condition in Studio.

3

Register a test student

Open your Student Registration Form (Form 1). Use a second Google account you control as the test student. After submitting, within 1–2 minutes a student document should appear in the test account's Shared With Me. Open it — verify it has the four zones (feedback header, prompt content, response area, CONFIG_ID footer).

4

Submit a test evaluation from the student document

Sign into the test student's Google account. Open their document. Write at least 25 words in the response zone. Click 📊 AI Evaluation Panel → Run Assignment Check. You should see a "Submitted for Feedback" confirmation. Within 1–3 minutes, feedback should appear at the top of the document.

If feedback doesn't appear within 5 minutes: check the Central Ledger → STAGING_PIPELINE tab. If a row is stuck IN_PROCESS, use ⚙️ Admin Controls → Reset Stuck Pipeline Row in the Central Ledger spreadsheet.

5

Test the Turn-In Form

Once the student document shows a [SYSTEM: APPROVED] stamp, open the Central Turn-In Form URL (in your Admin Setup Details). Submit using the test student's Google account identifier and the document URL. The teacher (you) should receive a verified submission notification email.

6

Check both dashboards

Open the Teacher Dashboard URL — verify the test student appears with status COMPLIANT. Open the Student Dashboard URL while signed in as the test student — verify their assignment appears with a submitted status.

✅
If all six checks pass, the system is fully operational and ready for teacher onboarding.
