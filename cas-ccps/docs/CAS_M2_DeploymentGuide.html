Phase 4 · ~2–3 hours

Configure
Studio Flows

Three flows in Google Workspace Studio. Keep CAS_Flow3_Flow4_Specification.html open in another tab — it has the exact system prompts, temperatures, and field mappings for all three flows.

✓
Step 1 of 6
Open Google Workspace Studio and create Flow 5 — Bridging Flow
Create this flow first because Flow 3 depends on it running before generation. Flow 5 is the simplest — temperature 0.4, max 150 tokens, one input field, one output field.
SettingValue
NameCAS — Bridging Flow
TriggerWarmUpQueue · Status = PENDING_BRIDGE — no compound condition needed; Script 24 only writes this status when a prior scored response already exists
Temperature0.4
Max tokens150
Inputflow5_prior_response · pacing_prior_connection · course_name from lesson_context_snapshot
OutputWrite to bridge_output (col 21) · Set status = PENDING
System promptSee CAS_Flow3_Flow4_Specification.html → Flow 5 section
Runs on its own PENDING_BRIDGE row, then promotes that row to PENDING — this hand-off is what actually enforces "before Flow 3," not a compound trigger condition on Flow 5. A student with no prior response never reaches PENDING_BRIDGE at all; their row starts at PENDING directly and skips Flow 5 entirely.
✓
Step 2 of 6
Create Flow 3 — Warm-Up Generation (Mode A: anchor-aware)
The primary generation flow. Runs after Flow 5. Checks for warmup_anchor in the snapshot — if present, personalizes it (Mode A). If null, generates from scratch (Mode B).

The doc structure: bridge paragraph (if bridge_output present) → separator → warm-up prompt → response line → student response zone.
✓

Evaluates student responses after Script 25 extracts the text and queues the row for AI scoring. Returns grammar and engagement scores plus brief pedagogical feedback.

Phase 5 · ~30 min

Smoke test
the full pipeline

Run the complete pipeline manually end-to-end before the first overnight cron. This catches any integration issues before real student data is involved. Do this the day before classes start.

✓
Step 1 of 8
Log a lesson via the Teacher Dashboard
Open your Teacher Dashboard URL. Click New Lesson in the header. Fill in: lesson date (tomorrow's date), learning objective, activity description, 2–3 competencies from one of your courses. Click Log lesson.

Confirm immediately:

  • Toast: "Lesson logged. Alignment will be recorded automatically."
  • LessonContext tab: one new row, status = ALIGNMENT_LOGGED
  • AlignmentLog tab: one row per competency selected
✓
Step 2 of 8
Run updateAllStudentProfiles() from Script 23
Simulates the 3:00am Stage 1 cron. Builds StudentProfile rows for all enrolled students. After running, open StudentProfiles tab — one row per student, with evaluation signals and warmup_scores populated from Module 1 history.
Students with no Module 1 history get empty evaluation_signals — correct. Shadow matrix will be empty {} until the first scored warm-up night.
✓
Step 3 of 8
Run syncArtifactCompetencies() from Script 31
Simulates the 3:05am artifact sync. Reads STAGING_PIPELINE for COMPLETE assignments, joins to Teacher Matrix competency_ids, updates StudentProfiles. If no assignments are tagged yet, logs "No competency tags found" — expected.
✓
Step 4 of 8
Run buildWarmUpQueues() from Script 24
Simulates the 3:30am Stage 3 cron. Reads the lesson you logged in Step 1 (tomorrow's date), determines which periods meet tomorrow by date parity, and builds one WarmUpQueue row per enrolled student in those periods.

Confirm in WarmUpQueue tab:

  • One row per student in the period(s) meeting tomorrow
  • Status = PENDING for a student with no prior scored warm-up, or PENDING_BRIDGE for a returning student with one — on a fresh deployment with no warm-up history yet, expect every row to be PENDING
  • lesson_context_snapshot is populated JSON (not empty)
  • student_profile_snapshot is populated JSON
  • Snapshot contains warmup_anchor if pacing guide was imported
  • Snapshot contains competency_rubrics array
✓
Step 5 of 8
Trigger Flow 5 (if any PENDING_BRIDGE rows exist) and Flow 3
In Studio, if step 4 produced any PENDING_BRIDGE rows, manually trigger Flow 5 on one of them first — its own final step promotes that row to PENDING once bridge_output is written. On a fresh deployment with no warm-up history, skip straight to Flow 3 below; every row is already PENDING. Then trigger Flow 3 on a PENDING row.

Confirm:

  • Flow 5 (if triggered): bridge_output (col 21) populated with 2–3 sentences, status set to PENDING
  • Flow 3: warm-up doc created in student Drive folder
  • Flow 3: doc_id + doc_url written to queue row
  • Flow 3: archetype (col 19) populated
  • Flow 3: status = DELIVERED
  • WarmUpRegistry: one new row

  • WarmUpRegistry row: total_score populated

  2. Run generateWarmUpReport() from Script 25 → confirm a grade report Doc is created, ReportRegistry row written (type: WARMUP_TERM)

Confirm nightly cron is ready
The system is ready to run autonomously. Tonight's cron will be the first live run. You don't need to do anything.

Before logging off:

  • Confirm ClassSchedule has the correct day_type for tomorrow's calendar date
