GenerativeWarm-Ups

Student-specific cognitive entry points generated overnight from lesson context and individual learning history. Scored nightly by AI against a 10-point rubric.

4 New Tabs 3 New Scripts 2 Studio Flows 10-Point Scoring Rubric Depends on M1 + M2 Lightweight
What this builds

The system in plain language

Each evening, the teacher submits a lesson context for the next class. At 3am, student profiles are updated from evaluation history and competency logs. At 6am on class days, Studio Flow 3 generates one personalized warm-up doc per student and delivers it to their Drive. Students arrive to a prompt shaped by their own learning history. Class discussion follows. That night, the 3am cron evaluates their responses against a 10-point rubric and writes brief feedback back into each doc.

Reads from M1

Ledger · ReviewQueue · STAGING_PIPELINE

  • Student roster per teacher/period
  • Evaluation outcomes and timestamps
  • Assignment feedback history
Reads from M2 Lightweight

LessonContext · AlignmentLog · CompetencyRegistry

  • Tomorrow's lesson objective and vocabulary
  • Competencies addressed per lesson
  • Full competency text for Flow 3 context
Writes new

StudentProfiles · WarmUpQueue · WarmUpRegistry · ClassSchedule

  • Aggregated student learning signals
  • Per-student pipeline state per lesson
  • Doc registry for all warm-up artifacts
  • Block schedule day-type configuration
◈
Block schedule awareness: Classes meet on odd or even calendar days (derived from the date's parity), except first period which meets daily. Period day types are configured once in the ClassSchedule tab during setup. The 3am cron checks tomorrow's date parity, identifies which periods meet, and only builds WarmUpQueue rows for classes that have a LessonContext submitted for that date.
Evaluation rubric

10-point scoring system

Word count is computed deterministically by Script 25 before Flow 4 runs. Grammar and engagement are evaluated by Flow 4. The AI never counts words — it only judges quality.

Component Criteria Points Judge
Word Count — 6 pts maximum
30+ words Meets full threshold 6 Script 25
25–29 words Near threshold — partial credit 5 Script 25
15–24 words Minimal attempt 3 Script 25
Under 15 words Insufficient 0 Script 25
Grammar & Sentence Structure — 1 pt maximum
Meets standard Cohesive sentences, no significant errors 1 Flow 4
Does not meet Significant errors impede comprehension 0 Flow 4
Engagement — 3 pts maximum
Genuine Directly addresses the prompt with original thought 3 Flow 4
Surface On-topic but formulaic or thin 2 Flow 4
Minimal Tangentially related or very thin 1 Flow 4
Off-topic / filler Does not engage with the prompt 0 Flow 4
Extra Credit
Feedback reply Student wrote a reply to Flow 4's feedback before next class +1 Script 25
Maximum per warm-up (without extra credit) 10
◈
Extra credit detection: Flow 4 stamps its feedback with a delimiter marker (── FEEDBACK ──) when writing to the warm-up doc. Script 25's 3am run checks for any text written after that marker. If text exists and is at least 10 words, extra_credit = 1. This is stored in WarmUpQueue and added to the student's WarmUpRegistry score. The extra credit reply is also captured as a signal in StudentProfiles — students who consistently engage with feedback receive harder provocations in subsequent warm-ups.
◈
Zero-response handling: If Script 25 finds no text in the response zone (word count = 0), it stamps the doc INCOMPLETE with score 0 and skips Flow 4 entirely. Flow 4 is never called with an empty response. This prevents wasted API calls and avoids Flow 4 generating feedback for a student who simply wasn't present.
Execution schedule

Two cron jobs, four stages

The 3am job runs three stages in sequence. The 6am job is Studio Flow 3. Together they form a pipeline that completes before students arrive.

// ── 3AM NIGHTLY CRON ───────────────────────────────────────────────────────── // Runs every night. Three stages execute in sequence. STAGE 1 — Script 23 (StudentProfileManager) → reads Ledger for all students (email, name, google_id, period) → reads AlignmentLog for competency coverage per student → reads STAGING_PIPELINE + ReviewQueue for evaluation outcomes → reads previous WarmUpQueue rows for warm-up score history → detects extra credit replies in warm-up docs (text after FEEDBACK stamp) → upserts one row per student in StudentProfiles structured analytic indicators + one-sentence feedback note per eval competency coverage map, warm-up score history, extra credit count STAGE 2 — Script 25 (WarmUpWriter — evaluation job) → scans WarmUpRegistry for yesterday's rows where score IS NULL → for each: opens warm-up doc, extracts RESPONSE zone text → counts words deterministically → computes word count score (0/3/5/6) → if word count = 0: stamp INCOMPLETE, score = 0, skip Flow 4 → if word count > 0: write word count score, set status PENDING_EVAL → Studio Flow 4 picks up PENDING_EVAL rows evaluates grammar (0/1) + engagement (0/1/2/3) writes { grammar, engagement, feedback } to WarmUpQueue row → Script 25 receives result, computes total score → writes score to WarmUpQueue + WarmUpRegistry → writes brief feedback into warm-up doc below student response → marks WarmUpQueue row SCORED STAGE 3 — Script 24 (WarmUpBridge — queue builder) → determines tomorrow's date → checks parity (ODD / EVEN) → reads ClassSchedule for periods matching tomorrow's day type + DAILY → reads LessonContext for lessons with lesson_date = tomorrow skips if no LessonContext found for that period (no class = no warm-up) → reads Ledger for enrolled students per teacher + period → reads StudentProfiles for each student (fresh from Stage 1) → writes one row per student to WarmUpQueue lesson_context_snapshot (JSON), student_profile_snapshot (JSON) status: PENDING → deduplication: skips if lesson_id + student_email already exists // ── 6AM CLASS-DAY CRON ─────────────────────────────────────────────────────── // Runs every morning. Studio Flow 3 is the only actor. Studio Flow 3 (Warm-Up Generation) → reads WarmUpQueue for PENDING rows → for each student: generates personalized warm-up prompt reads lesson_context_snapshot + student_profile_snapshot from queue row generates prompt — topically anchored, student-specifically angled → creates Google Doc in student warm-up folder [Admin Root]/[Subject]/[Teacher]/[Period]/Warm-Ups/[Student Name]/ stamps doc: PROMPT zone + RESPONSE zone (student writes here) → shares doc with student as editor → marks WarmUpQueue row DELIVERED + writes doc_id → Script 25 (post-generation job) registers doc in WarmUpRegistry
◈
Why stages run in sequence: Stage 1 must complete before Stage 3 so that WarmUpQueue rows are built with fresh StudentProfile snapshots. Stage 2 (scoring yesterday's warm-ups) runs between them so the extra credit detection in Stage 1 has the previous night's scored data available. Flow 3 runs at 6am rather than 3am to ensure profile snapshots are as current as possible and to minimize the window where a doc sits in a student's Drive before class.

Upsert pattern: Script 23 searches for an existing row by student_email. If found, it updates in place. If not found, it appends. AI layer

Two Studio Flows

Flow 3 generates. Flow 4 evaluates. Neither touches data structures directly — they read from and write to WarmUpQueue rows via the Sheets connector. Scripts handle all tab management.

Studio Flow 3 — Warm-Up Generation

Trigger: WarmUpQueue row with status PENDING · Runs at 6am · Per-teacher lane architecture from Module 1

◈
Prompt architecture — four student archetypes: Flow 3 receives the lesson context and student profile snapshot. Based on the student's avg_engagement_score, evaluation_signals, and competency_gaps, it selects one of four prompt angles: (1) Paradox — for students strong conceptually but weak on application; surfaces a genuine contradiction in the subject matter that the lesson resolves. (2) Concrete scenario — for students strong on application but weak conceptually; grounds the abstraction in a real industry situation. (3) Bridge — for students with competency gaps in today's duty area; connects today's lesson to prior work they have covered. (4) Provocation — for students strong across the board; a genuine intellectual challenge that has no easy answer and rewards prior knowledge. The prompt is always 3–5 sentences, never a list, never a fill-in-the-blank.
◈
Doc structure Flow 3 must stamp: The warm-up doc needs two clearly delimited zones so Script 25 can reliably extract the response. Zone 1: ── WARM-UP PROMPT ── ... ── END PROMPT ──. Zone 2: ── YOUR RESPONSE ── (student writes below this line). Script 25 extracts everything after the response delimiter for word count and evaluation. Flow 3 must not put any text after the response delimiter.

Studio Flow 4 — Warm-Up Evaluation

Trigger: WarmUpQueue row with status PENDING_EVAL · Runs as part of 3am cron Stage 2

Flow 4 receives three inputs: the original warm-up prompt, the student's response text, and the word count score already computed by Script 25. It evaluates only grammar/structure (0 or 1) and engagement (0, 1, 2, or 3). It must return a structured JSON response — no prose, no markdown.

Flow 4 expected JSON response
{ "grammar": 1, // 0 or 1 "engagement": 2, // 0, 1, 2, or 3 "feedback": "Strong connection to branding concepts but the application to event sponsorship could go deeper. Consider how exclusivity affects perceived value." // feedback: 1-3 sentences. Written into warm-up doc. Student reads before next class. // Never reveals the score. Never says "you got X points". Pedagogical, not evaluative in tone. }
◈
Feedback tone constraint: Flow 4's feedback must never mention points, scores, or grades. It is pedagogical — it advances the student's thinking, not their grade anxiety. The feedback is what the student sees when they open their doc before next class. It should make them want to think more about the topic, not calculate their percentage. The score is stored in the system; the feedback is for the student.
◈
Extra credit reply detection: Flow 4 stamps its feedback with ── FEEDBACK ── at the start and ── END FEEDBACK ── at the end when writing to the doc. Script 25's next 3am run reads the doc and checks for any text after ── END FEEDBACK ──. If 10+ words exist there, extra credit = 1. The student never sees instructions to reply — the invitation is implicit in the feedback quality.

CompetencyRubrics — SOL correlations added

Each rubric now carries sol_correlations — a subject-keyed object of SOL codes (e.g. {"English": ["9.C","9.DSR","9.RI"], "Mathematics": ["A.1"]}). 197 of 221 competencies have SOL data. The 24 without are CTSO/WBL tasks, holistically assessed by VDOE design. Also added: definition (official VDOE definition text) and required (R or O). Flow 3 can reference SOL subject areas as personalization signals — a student whose shadow matrix shows low engagement on History & Social Sciences-correlated competencies is a different target than one strong there.

Flow 5 — Bridging Flow (new)

Flow 5 runs at 6am before Flow 3 on PENDING queue rows that have a flow5_prior_response in their snapshot. Temperature 0.4 · Max tokens 150. Generates a 2–3 sentence bridge between the student's most recent scored response and today's lesson using pacing_prior_connection from the pacing guide. Output written to bridge_output (col 20 of WarmUpQueue). Flow 3 prepends when present. Skips students with no prior history — strictly additive.
