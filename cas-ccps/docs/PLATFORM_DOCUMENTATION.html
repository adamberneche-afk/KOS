Foundation

The Design Principle

Every module in this platform is built on a single idea. Everything else follows from it.

01

Automate the prerequisite

Define what "ready for human attention" means in any context. Build a gate that enforces it automatically. The teacher's attention arrives only at the right moment.

02

Protect the human moment

Every piece of friction removed is an investment in the human relationship it was obscuring. The goal is never efficiency — it's presence.

03

Never replace judgment

The system verifies, surfaces, and scaffolds. The teacher decides, responds, and knows the student. Automation flags; humans act.

◈
The platform's north star: a classroom where teacher attention is concentrated precisely where it does the most good — in the messy, uncertain, genuinely human middle of the learning process, where no algorithm can substitute for a skilled adult who knows the student in front of them.
Platform Structure

Three Modules,
One Platform

Each module is independently deployable and useful. Together they form a complete learning environment where automation serves human connection at every stage of the learning cycle.

MODULE 01

Evaluation Engine

Student-facing iterative feedback with turn-in gating. The prerequisite system for final submission.

PRODUCTION READY 21 Scripts 2 Studio Flows Pilot Active

Students receive AI-powered feedback within 1–3 minutes against teacher-defined rubric criteria. Multiple revision cycles. Turn-in gate requires verified passing evaluation before submission reaches the teacher. Teacher only sees work that met the standard.

MODULE 02

Lesson Intelligence

Lesson framing, competency alignment, and personalized warm-ups. The prerequisite system for instruction.

SPECIFICATION ~8 Scripts 2 Studio Flows Build Ready

Teacher inputs lesson context once. System generates learning objectives, competency alignment documentation, and personalized warm-ups for each student. Teacher begins instruction knowing the room — which students are ready, which concepts are fragile.

MODULE 03

Student Profile

Longitudinal knowledge state built from evaluation and lesson history. The connective tissue between modules.

DESIGNED ~4 Scripts Depends on M1 + M2

Accumulates concept-level mastery data from every evaluation and warm-up. Powers personalized warm-up differentiation. Surfaces patterns to teachers. Becomes a longitudinal learning record across terms and years.

INFRASTRUCTURE

Shared Platform Core

Configuration, setup wizards, deployment tools, dashboards, and impact tracking shared across all modules.

PRODUCTION READY Scripts 00 + 16–21 All modules

Unified setup wizard with role detection, AutoInstaller, _CONFIG tab persistence for cloned sheets, checkpoint-safe deployment, term management, health monitoring, and impact dashboard. Shared by all modules.

Module 02 — Specification

Lesson Intelligence

What gets built next. Full specification for the lesson framing, competency alignment, and warm-up system.

Teacher input

Lesson Context Form

One form per lesson. What are students doing, what should they be able to do after, which vocabulary is central, which competencies does it address, what did we do last time. Submits to LessonContext tab. Takes 5–10 minutes.

System output → Teacher

Lesson Frame Document

Auto-generated from lesson context. Learning objective in teacher language. Competency alignment mapped. Suggested warm-up question. Connection to prior lesson explicit. Teacher reviews and approves.

System output → Students

Student-Facing Warm-Up

Objective in plain language. Warm-up prompt connected to prior work or today's vocabulary. Personalized based on each student's evaluation history when Module 3 profile data is available.

System output → Admin

Competency Alignment Log

Auto-accumulating record of every lesson mapped to competency framework. Date, description, competencies addressed, objective. Becomes end-of-term documentation artifact with no additional teacher effort.

Teacher dashboard

Pre-Lesson Readiness View

Which students completed the warm-up. Which concepts are fragile across the class. Coverage map showing which competencies have and haven't been addressed this term. Teacher opens class already knowing the room.

Setup — once per course

Competency Registry

A structured Google Sheet listing all competencies for this subject and grade level. 20–40 items. Built once from district framework. Drives the lesson form dropdown and the alignment log. The one setup investment that can't be skipped.

Key Architectural Decisions

  • SEPARATION Module 2 is a separate deployment from Module 1. Same Central Ledger, new tabs and scripts. A school can run Module 1 indefinitely without Module 2. Module 2 deploys by adding tabs, scripts, and flows to an existing Module 1 installation — no changes to existing scripts.
  • DATA FLOW Student evaluation outcomes feed Module 2 warm-up personalization. Script 23 reads evaluation results from Module 1 and writes concept-level signals to StudentProfiles. Module 2 reads those profiles when generating warm-ups. The integration is opt-in — warm-ups work without profiles, just less personalized.
  • INFRASTRUCTURE Script 16's setup wizard is extended, not replaced. Script 28 adds a Module 2 setup phase to the existing wizard. Same role detection, same checkpoint system, same Admin Manual. Teachers don't need a new manual.
  • PRIVACY Student profiles never leave Google Workspace. Same architectural principle as Module 1 — no external vendors, no data export, no additional DPAs. The competency registry and lesson context are entirely within the school's existing infrastructure.
  • SCALE Same per-teacher lane architecture applies to warm-up generation. Script 24 uses the same queue-and-pointer pattern as Script 03. Each teacher's warm-up generation queue is independent. Studio Flow 3 is subject to the same single-ledger concurrency constraints — same 10–15 teacher ceiling applies.
