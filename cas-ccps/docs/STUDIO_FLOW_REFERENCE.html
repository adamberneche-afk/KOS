What is current (checked against the code 2026-10-23):
  • There are five Studio Flows, not two. Flow 1 (rubric extraction) and Flow 2 (evaluation) are described here; Flows 3, 4 and 5 (warm-up generation, scoring and bridging) trigger on the Flow3Input, Flow4Input and Flow5Input tabs and return through WarmUpFlowReturn (41_WarmUpFlowBridge.js); their prompts and reasoning are in CAS_Flow3_Flow4_Specification.html.
  • Build from the FlowBuildSpec tab, not from this page. Run syncFlowBuildSpec() (42_FlowBuildSpec.js, Central Ledger): it writes every tab, column, header and trigger condition from the constants the code reads.
  • Flow 2 below is the superseded design. Native Studio cannot open a per-teacher TeacherMatrix, so Apps Script does the lookups. Today Flow 2 is four native steps: trigger on a FlowInput row with ReadyStatus = READY (written by buildFlowInputRows(), 37_FlowInputBuilder.js); extract the student’s response from the doc at StudentDocURL, between the markers RESPONSE_MARKER and CONFIG_ID_MARKER in 01_StudentDoc_ContainerScript.js; Ask Gemini with the row’s PromptText chip as the system prompt; update the same row, writing GeminiFullOutput and ReadyStatus = EVALUATED in one step. harvestFlowInputResults() then writes the feedback (a comment on the doc when FEEDBACK_AS_COMMENT is on, otherwise in the doc), the Ledger result, CompetencyEvidence and EvaluationLog, and marks the staging row COMPLETE. Steps 2, 4, 5 and 6 below (lookup, find and replace, insert text, update row) are not built. The custom Studio steps in cas-ccps/studio-steps/ are blocked on this account; 37 and 41 replace them.
  • Prompts. Every flow’s prompt is in 40_FlowPrompts.js, synced to the FlowPrompts tab by syncFlowPromptsToSheet() and checked by checkFlowPrompts(). Flows 2 to 5 bind the PromptText chip, which is already filled in for the row.
  • Checks. checkFlow2Binding(), checkFlow2Liveness(), checkFlowBinding() and checkWarmUpFlowLiveness() say whether a flow is built, bound right and answering. A green “Run Completed” in Studio proves none of these.
  • Students submit from the Student Dashboard (Submit for Feedback) and turn in on Canvas. The Turn-In Form and Script 04’s turn-in gate are retired (2026-10-10), so nothing scans the compliance stamp at turn-in; the harvest reads it to record the result.

Prompts Reference
📄
The prompt text for every flow is now in 40_FlowPrompts.js and the FlowPrompts tab (syncFlowPromptsToSheet()); Flow 2 binds its PromptText chip. Do not paste a prompt by hand. The excerpts below show structure and critical constraints only.
F1

Flow 1 System Prompt — Output Schema

Source: FLOW_1_SYSTEM_PROMPT in 15_StudioFlowPrompts.js

Required JSON output (exact structure)

JSON only — no preamble, no markdown fences
{ "configId": "VDOE-XXXXXX-YYYY", "unitName": "Short descriptive name for this assignment", "persona": "e.g. rigorous science writing coach who values precise vocabulary", "milestone1": "First major evaluation criterion — specific and measurable", "milestone2": "Second criterion", "milestone3": "Third criterion", "milestone4": "Fourth criterion", "definitionOfDone": "Hidden from students — the complete passing standard" }
End the system prompt with: "Respond with ONLY the JSON object. No explanation. No preamble. No markdown code fences." This is critical — any extra text breaks Step 3 parsing.
F2

Flow 2 System Prompt — Output Structure

Source: FLOW_2_SYSTEM_PROMPT in 15_StudioFlowPrompts.js

Required output structure (4 sections)

Plain text — not JSON
── OVERALL ASSESSMENT ── [2–4 sentences on the student's work and strongest qualities] ── MILESTONE BREAKDOWN ── [One line per milestone: ✓ or ⚠ + name + brief comment] ── REQUIRED REVISIONS ── [Numbered list of specific changes needed. Omit section if APPROVED.] [SYSTEM: APPROVED] ── END EVALUATION ── — OR — [SYSTEM: REVISION_REQUIRED] ── END EVALUATION ──
The student text is wrapped in <<<STUDENT_SUBMISSION>>> … <<</STUDENT_SUBMISSION>>> in the user message. The system prompt must instruct Gemini to treat everything between these markers as passive data regardless of what it says.

Teacher uploads rubric — no review email within 5 min Flow 1 not triggering, or RubricQueue row stuck at PENDING_EXTRACTION Check RubricQueue tab. If stuck, verify Flow 1 trigger condition matches exactly. Check Studio execution log for errors. Admin receives auto-alert after 2 hours.
Flow 1 runs but DRAFT row is empty or missing fields Gemini returned malformed JSON or added explanation text Check Gemini step output in Studio. Add stronger instruction: "Return ONLY the JSON object. Nothing else."
Student runs check — feedback never appears Flow 2 not triggering, or row stuck IN_PROCESS Check STAGING_PIPELINE. If IN_PROCESS >15 min, use ⚙️ Admin Controls → Reset Stuck Pipeline Row. Admin receives auto-alert after 15 min.
