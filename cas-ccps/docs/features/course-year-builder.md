# Course year builder (script 51)

Moved from `cas-ccps/README.md` on 2026-11-21 (meta/AUDIT_STRUCTURE_2026-11-20.md,
4.2); the README's "Features" table links every file in this folder.

`51_CourseYearBuilder.js` (Central Ledger) loads the 8175/8177 course data and
keeps the next week of lessons filled in, so warm-ups and the dashboards run on
real content. Everything it writes is teacher- and class-level.

| Function | What it does |
|---|---|
| `importCourseData()` | Runs the registry (22b), pacing guide (31) and rubric (32) importers, which find `CompetencyRegistry.csv`, `PacingGuide_CAS_Context.json` and `CompetencyRubrics.json` in Drive by name, then `checkCourseData()`. Safe to re-run. |
| `checkCourseData()` | Compares the live tabs with the repo's data (113 + 108 competencies and rubrics, 20 units, readable unit dates), and seeds the `NoSchoolDays` tab from the CCPS 2026-27 calendar (a copy of leader-hub's; a test keeps them equal). Edit that tab for snow days. |
| `previewUpcomingLessons()` / `buildUpcomingLessons()` | For each school day in the next 7 days and each ClassSchedule period meeting it, writes a LessonContext row from that course's pacing-guide unit through `onLessonContextSubmit_()`, so alignment logging and the Lesson Frame Doc happen as for a hand-entered lesson. A slot that already has a lesson is never touched; a teacher's own submission for a slot replaces the drafted one. A period where both courses meet gets one lesson per course (`period_or_class` `1 (8175)`, `1 (8177)`), and its warm-ups go to that course's students only (Ledger CourseName). |
| `previewRemoveDraftedLessons()` / `removeDraftedLessons()` | Unbuild: marks every drafted lesson dated today or later SUPERSEDED and trashes its Lesson Frame Doc, so the next build drafts those slots again. Lessons you entered are never touched. |
| `previewAssignmentSeed()` / `seedAssignments()` (53) | Writes LIVE TeacherMatrix assignments from the repo's unit rubrics, without Studio Flow 1: one row per unit and course (Config ID `CAS-<unit>-<code>`, e.g. `CAS-S1-U1-8175`), with its prompt-template Doc, in the matrix MatrixRegistry names (adding the TeacherMatrix tab if it's missing). Units come from the Script Property `SEED_UNITS` (`S1-U1` or `S1-U1,S1-U2`), else each course's current pacing unit. A unit already in the matrix is never written again. The data is `53b_UnitAssignmentData.js`, generated by `tools/cas-ccps/build-unit-rubrics.js`. |
| Competency tiers (`curriculum/lessons/COMPETENCY_TIERS.json`) | Per assignment, decided 2026-10-20: a **primary** competency (Milestone 1, must be MET), one or two **secondaries** (Milestones 2–3, at least PARTIALLY MET; Milestone 4 is "completes every part of the task", also at least PARTIALLY MET) and **tertiaries** (never required). The generator writes them into the Definition of Done with a PASSING RULE line, and adds "What your work needs to show" (and "You can also show") to the student's task. Flow 2 names the tertiaries the work shows under ALSO SHOWN, which the student sees, and on an `[ALSO_SHOWN: [...]]` line, which the harvest (37) records as MET evidence and strips. An APPROVED the outcomes don't support (or a REVISION_REQUIRED they do) is malformed since 2026-11-15: the harvest sets it aside and re-arms it, instead of delivering it as revise. Every lesson assignment (8175 L01–L36, all 31 8177 lessons) drafted from its task and approved 2026-10-20, tweaked as lessons are taught; an assignment with no entry keeps the untiered criteria. After editing the file: run the generator, push, then `refreshAssignments()`. |
| Video links (`curriculum/lessons/VIDEO_LINKS.json`) | The videos a lesson's task tells students to watch (8175 L06 and L34), keyed by lesson, each `{ title, url }` (https). The generator adds a "Video: <title> (<url>)" line under the task's "Watch" line; new student docs (02) and the Canvas cartridge make it a link; `previewVideoLinkRefresh()` / `applyVideoLinkRefresh()` (53) add it to docs already made, above the student's writing only, once. An empty list is a lesson still waiting on its link (2026-10-24: both). After adding a link: run the generator and the cartridge builder, push, `refreshAssignments()`, the refresh, and re-import the cartridges. |
| Learning objectives, owned by the student (`curriculum/lessons/STUDENT_CRITERIA.json`) | Per assignment, one "I can …" sentence per competency (primary, secondaries, tertiaries): the skill, and how this task's work shows it. Drafted and approved 2026-10-24 for every lesson (draft 2: "I can", the operator's direction; `meta/STUDENT_WORK_PLAN_2026-10.md`); `_concerns` lists tertiaries the task gives little room to show, all kept. The generator puts them in the student's task under "What your work needs to show" (a competency without one keeps its title) and carries them as each lesson's `objectives`; the seeder and `refreshAssignments()` write them to the TeacherMatrix's `StudentObjectives` column (21, JSON), where the reflection questions read them (00). `student-criteria.test.js` keeps one per competency in `COMPETENCY_TIERS.json`. After editing the file: run the generator and the cartridge builder, push, then `refreshAssignments()`, which also rewrites each LIVE row's prompt doc so new student docs get the task as the repo has it. |
| Lessons in parts (`curriculum/lessons/PARTS.json`) | A lesson split into parts, one work file each, unlocked in order (`meta/STUDENT_WORK_PLAN_2026-10.md`, Phase 3): each part's marker in the prompt, work file, tiers, criteria in the student's words and vocabulary. The generator makes each part an assignment of its own in 55b's `LESSON_PARTS` and refuses a split that leaves a lesson competency out. First lesson: 8177 Market Research (Appendix B, approved 2026-10-27). The other 34 multi-part lessons (5 in 8175, 29 in 8177) were drafted in its pattern and approved together on 2026-10-28; the teacher's copy of all 35 is `meta/LESSON_PARTS_2026-10.md`. New drafts wait in `curriculum/lessons/PARTS_DRAFTS.json`, which the builder never reads. |
| `previewAssignmentRefresh()` / `refreshAssignments()` (53) | Brings rows already in the TeacherMatrix up to the repo's criteria: the four milestones, the Definition of Done and the milestone competency IDs, for each ConfigID the repo generated (lessons and units). Nothing else in the row changes; teacher-made rows are left alone. Flow 2 reads the row when a student submits, so the next submission uses it. Run after a generator change to criteria (since 2026-10-20: the Definition of Done carries the task text, a competency's indicators are examples rather than a checklist, and a competency is judged only by what the task asks; since 2026-10-19: a competency with no state indicators uses the state definition, grading notes about work outside the doc are dropped, and a milestone holding several competencies lists all their IDs, each getting evidence). |
| `installLessonPlanTrigger()` | Runs `buildUpcomingLessons()` daily near 2am, before the 3:30am warm-up queue reads tomorrow's lessons. `removeLessonPlanTrigger()` undoes it. |

Units overlap in the pacing guide (S8-U2, 8177 only, runs inside S7-U1, 8175
only, and S7-U2/S8-U1), so `resolveUnitForCourseDate_()` (31) picks the unit
the course actually takes. `getWarmUpAnchor_()` uses it too: an 8177 class
used to get no warm-up anchor for those weeks.

Assignments still go through the Rubric Upload Form and Flow 1, so you
confirm each one. `curriculum/unit-rubrics/` holds a rubric and prompt
template per unit and course to paste in, generated by
`tools/cas-ccps/build-unit-rubrics.js`. Each assignment is the work the
unit's lesson card planned: its work product, the course's role, the
activity and the course's "goes deeper" extension. The unit's competencies
are the criteria.
