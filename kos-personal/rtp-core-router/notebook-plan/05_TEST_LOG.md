## What the runs changed in V6.0

- The BRAIN_TRUST_INDEX fetch is gone; Vector State, the vision and onboarding status come only from the primer, and an unreadable count is unknown, not 0.
- `@Startup` retrieves the primer first; if it can't, it says `[UNCONFIRMED — KOS_LATEST_PRIMER]` and gives no state.
- Cold Boot fires only when the primer itself reports 0 sessions.
- A FLAGGED Data Quality block qualifies every Vector State claim, and health is never called GREEN while flagged.
- "Active Files in Context" became "Sources this turn": only sources actually retrieved.

## What the V6.0 runs changed in draft 2

- `@Startup` runs only when the message contains `@Startup`, not on any first message.
- Apps are called only from chips in the operator's message: `@Startup` goes out with `@Google Calendar`, `@Workspace` and `@Google Tasks`. Mail goes through `@Workspace`. A missing chip is `NOT INVOKED`; FAILED means the call returned an error.
- No persona cold-start block at startup; the FLAGGED qualifier appears once; citations name the source the claim came from.
- Every `KOS_*` briefing doc now carries `Notebook source: {NAME}.` under its stamp (`_writeStableDoc_`, `6_Governance.gs`). The router searches for that line.
- The ALIGNMENT pause resumes only on an explicit A, B or C.
- No calendar, inbox or task claim without an app call that turn, and no offers to create, send or schedule.
- RID is shown as R, I and D, and a request in a persona's domain scores above 0 for it.
- A request for student, roster, grade or CAS data gets "no access" and nothing else.
- The brief takes the primer's `Onboarding Day` line and Shadow Matrix `Engine mode` by name.
