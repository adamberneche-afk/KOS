# notebook-sources/

The notebook edition of each persona doc, for the RTP notebook (Phase 2
step 1 of `../notebook-plan/04_MIGRATION_AND_TEST_PLAN.md`; the Tier B
sources in `../notebook-plan/02_PRD.md` §5). Generated by
`tools/kos-personal/build-notebook-personas.js`; do not edit the
`PERSONA_*.md` files here.

A notebook retrieves passages, not whole docs. So each edition:

- **Core block:** opens with the persona's core block (`cores/<NAME>.md`), a
  summary of role, prefix, triggers, hard rules and hand-offs, each cited to
  its section. The full sections still govern.
- **Headings:** puts the persona name in every heading, so a passage from
  the middle of the doc still says whose rule it is.
- **Preamble:** drops the preamble (the "Gemini Gem System Prompt" label,
  version notes, addenda). That is history, kept in the canonical doc.

Everything else is the canonical `../PERSONA_*_V5_1.md`, unchanged. Council
Gems keep using the canonical docs (ADR-003): never attach the notebook to them.

## Changing one

Edit the canonical doc or its core block, then run
`node tools/kos-personal/build-notebook-personas.js`. The tests fail while an
edition is out of date. A core block must start `## <Persona Name> · Core`,
quote the doc's Mandatory Prefix exactly, and stay under 2,400 characters.

## Loading them into the notebook

1. Upload each `PERSONA_*_V5_1.md` here to Drive. Open it with Google Docs,
   which converts it, and name the Doc exactly as the file, without `.md`.
2. Check one converted Doc against this file: headings, the tables, the code
   blocks (unknown U6).
3. Add the six Docs to the notebook as sources.

## Inconsistencies in the canonical docs

The core drafts turned these up. The cores follow the section that states
the rule and don't try to reconcile it with the others. Each is worth fixing
in the canonical doc:

- **Prefix spelling.** MUSE and ARCHITECT give `[ THE MUSE]:` and
  `[ THE ARCHITECT]:` (a space where the other four have an emoji; probably
  lost), and their §10/§11 templates spell the prefix with no space.
- **CURATOR output.** §2.6 and §7 say "raw JSON only", but §9 puts a
  Verification Gate block before the JSON. §6 appends an `[🔧 AUTO-CORRECTED]`
  log after it, while §9 says nothing follows the closing `}`.
- **MUSE routing.** §5.3 sends Category C to Architect review, while §5.1,
  §5.2 and §7.1 send both B and C to the RTP.
- **ARCHITECT order.** §1 says every response opens with the mode, §4 puts the
  SCA "at the top", and the §11 template starts with the prefix.
- **AUDITOR citation.** §2 and §8 require a PIVOTS_AND_LESSONS entry for every
  critique, but the §9 template's `[📋 CONSTRAINTS CITED]` reads
  "[Lesson or Law]".
- **"No sections may be omitted"** (ARCHITECT §11, DEVELOPER §10) sits next to
  blocks the same template marks "if applicable".
