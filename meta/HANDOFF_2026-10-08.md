## What happened on 2026-10-08

### cas-ccps: the student and teacher paths, rebuilt for how the school works

Detail is in `cas-ccps/HISTORY.md`, newest entry.

- **Found live: students can't run the doc's script.** On the first lesson
  day the teacher saw the "📊 AI Evaluation Panel" menu on a student's doc
  and the student didn't. The district turns Apps Script off for student
  accounts. Students *can* open the Student Dashboard, a web app that runs
  as the admin. So **anything a student does must go through the
  Student Dashboard**, not a doc menu.
- **Canvas is the LMS.** Students turn in on Canvas (their document's link,
  as the cartridges already say) and the teacher grades there, separately.
  CAS's job is feedback and keeping the SCR current. The CAS Turn-In Form
  was never shared with students and is now gone from everything they see.
- **#115: Submit for Feedback on the Student Dashboard.** The dashboard
  reads the doc as the admin, applies the menu's minimums and queues the
  work. New `documents` scope on `student-dashboard`.
- **#116: SCR and next steps.** The teacher's SCR rule: one piece of
  evidence per assignment at its best outcome, and the suggestion is the
  average of the three best (Met 2, Partially met 3, Not met 4), rounded.
  Each evaluation block carries its own "What to do next": passing
  *suggests* turning in on Canvas and still offers another check. The
  Ledger moves to COMPLETE after an evaluation. Feedback is added at the
  **end** of the doc (the wording said "top").
- **#117: the Teacher Dashboard.** Each evaluation's result is recorded on
  the Ledger (columns 24–27). The dashboard opens on the current lesson
  and shows four states, because not checked and not passing are different:
  ⚪ not checked yet, ✏️ checked but not passing yet, ✅ passed, ↩️ passed
  before with the latest needing revision. Rows show checks, first pass
  and the latest suggested score.
- **Docs:** Student Quick Start, Teacher Reference Guide and Teacher Quick
  Start rewritten for the dashboard and Canvas; the architecture and admin
  references carry a "current as of 2026-10-08" note.
- **The identical "CAS - Master Student Template" projects** in the
  operator's Apps Script list are expected: copying a doc copies its bound
  script, so each student doc has one. Leave them (see Later).

## For an agent session picking this up

- **Read first:** this file, then the per-system handoff for your system.
- **Students can't run Apps Script.** Anything a student does goes through
  the Student Dashboard web app (`13`, runs as the admin). Don't build
  student features into the doc's bound script.
- **Canvas is the LMS.** Turn-in and grades happen there. CAS gives
  feedback and keeps the SCR; it never needs a turn-in of its own.
- **Evidence and states.** SCR counts one piece per assignment at its best
  (`30`'s `aggregateEvidence_`); the Teacher Dashboard's four states come
  from Ledger columns 24–27 (`37`'s `recordEvaluationResult_`). The Ledger
  is 27 columns wide (`LEDGER_COL_COUNT`).
- **Feedback is appended at the end of the doc** (`37`'s harvest). Text
  that tells students where to look must say so.
- **Deploy markers:** any change to a GAS project's files needs
  `node tools/deploy-drift/stamp.js <project>`, committed on its own. A
  change to `00_SharedConfig.js` touches all seven cas-ccps projects that
  include it.
- **Generated files:** never hand-edit them; run the generator (the root
  README lists them).
- **Checks before a PR:** `npm test`, `node tools/gas-lint/check.js`,
  `node tools/doc-currency/check.js` (zero errors is the gate),
  `node tools/coverage-gaps/check.js`. New top-level test files must be
  named in `README.md` (CI's docs-check). Tests that call into a whole
  project should load its file list from `tools/gas-lint/project-map.json`.
- **Sheets turns ID-like text into dates**; write such cells with format
  `@` and read them back through the existing text helpers.
- **FERPA:** student data never goes to Claude, the KOS Ledger or either
  notebook. Ask for logs with student names redacted.
- **The operator runs things live and pastes back logs.** Don't assume a
  run happened.
- **How this repo is worked:** one PR per piece of work from a `claude/*`
  branch; CI green before asking to merge; the operator says "merge" and the
  session merges with a merge commit; the operator then pushes `main`.
