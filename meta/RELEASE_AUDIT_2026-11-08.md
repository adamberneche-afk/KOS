## What each bucket needs (recommendations)

**Drive IDs and Docs links (524).**
- `drive-curation/` (269): a Drive inventory by design:
  `DELETION_MANIFEST.md` (62), `curriculum/Unit_Cross_Reference_Links.md`
  (33), `GEMINI_HANDOFF_INSTRUCTIONS.md` (2) and the two workbooks (172
  inside them). Recommend: the folder does not ship. Move it out of the
  published tree (to Drive, where the files it lists live), or keep it only
  in a private repo.
- `leader-hub/` (250): 238 are the lesson-plan table's `docId` values,
  119 in `src/09-wbl-lessonplans-procurement-finance-esports.html` and the
  same 119 in the assembled `student-leader-hub.html`; the rest are
  spreadsheet links in four docs (5), two document links on one line of
  `src/06` (and its assembled copy, 4), one labelled ID in `LH_02_INTEGRATION_GUIDE.md`,
  one `openById` in `LH_04_EMAIL_AUDIT.md`, one folder link in
  `drive-tools/LH_Drive_README.md`. Recommend: the lesson-plan IDs move to
  config read at run time (as CAS does with Script Properties), or the
  table carries titles only and the page looks the docs up; the docs'
  links become `<your sheet's URL>`-style descriptions.
- `tests/` (5): one document link repeated in
  `tests/cas-ccps/ledger-schema-guard.test.js`. Fixtures are where the #7
  leak was: replace it with a synthetic ID assembled at run time. **Fixed
  2026-11-08:** a made-up URL assembled at run time (`FAKE_DOC_URL`). The
  old ID is still in git history; rewriting history is decision 4 below.

**Apps Script web-app URLs (70).** All are the Student Dashboard's
`/a/macros/<domain>/s/…/exec` URL: `cas-ccps/data/deployment-urls.json`,
the same URL generated into the two Canvas cartridges (36 and 31
occurrences), and two LeaderHub docs. The cartridges need it: students
follow it from Canvas. Recommend: the cartridges stop being tracked (they
are generated; build them on the operator's machine), the JSON's URL comes
from config at build time, and the LeaderHub docs say "the web app URL".
Or the operator decides a deployment URL is not secret (it is behind the
school's sign-in) and the gate takes a rule for it.

**Tracked exports (10).**
- `drive-curation/Curriculum_Cross_Year_Index.xlsx` and
  `Drive_Curriculum_Catalog.xlsx`: Drive catalog workbooks, the same kind as
  the five removed on 2026-10-31. Recommend: remove (with the folder).
- `cas-ccps/curriculum/canvas-cartridges/8175.imscc`, `8177.imscc`: Canvas
  course exports generated by `build-canvas-cartridge.js`. Recommend:
  untrack and build on demand (the tests that compare them to the
  generator would build into a temp folder instead).
- Six CSVs in `cas-ccps/` (`data/CompetencyRegistry.csv`,
  `data/LessonPrimarySecondary_Seed.csv`, three in
  `data/sol-correlations/`, `curriculum/PacingGuide_CAS_Context.csv`):
  curriculum and standards data, not student data, and inputs to the
  generators. They are "exports" only by file type. Recommend: the
  operator decides whether curriculum data counts; if it does, they move
  to Drive and the generators read a local copy kept outside the repo.

**LICENSE (2).** The root has none, and `leader-hub/` has none;
`cas-ccps/` and `kos-personal/` do. Mothership is another repo (not
checked here). Recommend: choose under D11 and add both files in one PR.

**For review: 18 `.docx` files** (lesson cards, CAS module documentation,
the pacing guide, two SOL correlation documents). Their text was scanned
and holds no finding. Whether a district or VDOE document may be
republished is the operator's call (D11, release contents).

**Probably fine: 12 `appsscript.json` manifests.** Source, not exports;
they hold scopes and settings, no IDs (they produced no content finding).
